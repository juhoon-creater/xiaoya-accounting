# 小芽记账 App 第一版接口文档

## 1. 文档说明

| 项目 | 说明 |
|---|---|
| 文档状态 | 待评审，评审通过后作为 App 与后端联调依据 |
| 接口入口 | 本地开发统一通过 Gateway：`http://localhost:8080` |
| 接口前缀 | `/api` |
| 数据格式 | 请求和响应均为 UTF-8 编码的 JSON；删除、退出等操作也返回统一 JSON 响应 |

| 日期格式 | `YYYY-MM-DD`；月份格式为 `YYYY-MM`；时间格式为 ISO-8601 |

接口响应结构参考所附《api接口文档.pdf》的写法：每个接口分别说明接口信息、请求参数、请求示例、响应参数和响应示例。本项目使用 HTTP 状态码表达传输结果，并在响应体中提供稳定的业务错误码。

## 3. 公共约定

### 3.1 请求头

所有请求均发送：

| 请求头 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `Content-Type` | string | 有 JSON 请求体时必填 | 固定为 `application/json` |
| `Authorization` | string | 受保护接口必填 | 格式为 `Bearer {accessToken}` |

### 3.2 成功响应结构

所有成功响应均使用以下结构。创建资源使用 HTTP `201`，其他成功操作使用 HTTP `200`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | number | 是 | `1` 表示成功 |
| `msg` | string | 是 | 提示信息，成功时为 `success` |
| `data` | object/array/null | 是 | 接口返回数据；无业务数据时为 `null` |

示例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {}
}
```

### 3.3 失败响应结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | number | 是 | `0` 表示失败 |
| `msg` | string | 是 | 面向调用方的简要错误说明 |
| `errorCode` | string | 是 | 稳定的业务错误标识，客户端逻辑不得依赖 `msg` 文案 |
| `data` | null | 是 | 失败时固定为 `null` |

示例：

```json
{
  "code": 0,
  "msg": "账单不存在",
  "errorCode": "BILL_NOT_FOUND",
  "data": null
}
```

### 3.4 公共错误码

| HTTP 状态码 | `errorCode` | 说明 |
|---:|---|---|
| 400 | `INVALID_PARAMETER` | 缺少参数、格式错误或参数校验失败 |
| 401 | `UNAUTHORIZED` | 未登录、Token 无效、过期或已退出 |
| 403 | `FORBIDDEN` | 已登录，但无权执行该操作 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在，或不属于当前用户 |
| 409 | `USERNAME_ALREADY_EXISTS` | 注册用户名已被使用 |
| 500 | `INTERNAL_ERROR` | 服务端未预期错误；不得返回堆栈或敏感信息 |

### 3.5 身份与数据隔离

1. 注册、登录接口不需要 Token；其余接口均需要 Token。
2. 当前用户 ID 只能从服务端验证后的 Token/认证上下文取得。客户端不得传 `userId`，服务端也不得信任请求中的 `userId`。
3. 账单详情、修改、删除，预算读写和统计查询必须限定当前登录用户。访问其他用户资源时按资源不存在处理，返回 `404`，不泄露资源是否存在。
4. Gateway 负责路由，不等于完成了业务身份认证。业务服务必须验证 Token，或只信任经过安全校验的内部身份上下文。

### 3.6 字段枚举

| 字段 | 取值 | 说明 |
|---|---|---|
| `transactionType` | `EXPENSE`、`INCOME` | 支出、收入 |
| `category.type` | `EXPENSE`、`INCOME` | 分类所属收支类型 |
| `mood` | `开心`、`平静`、`后悔`、`焦虑`、`压力`、`未知` | 可选的 Demo 心情标签，是否进入首版待评审 |

## 4. 用户与认证接口

### 4.1 用户注册

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/users/register` |
| 请求方式 | POST |
| 接口说明 | 使用用户名和密码创建账号；注册成功后需单独调用登录接口 |
| 登录要求 | 否 |

#### 请求参数

请求类型：`application/json`

| 参数名 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `username` | string | 是 | `xiaoya` | 去除首尾空格后校验；长度 3-50；大小写不敏感且唯一 |
| `password` | string | 是 | `XyPass123` | 8-72 个字符；仅通过 HTTPS 传输；服务端以 BCrypt 哈希保存 |

#### 请求示例

```json
{
  "username": "xiaoya",
  "password": "XyPass123"
}
```

#### 响应参数

HTTP 状态码：`201 Created`

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | number | 是 | 成功固定为 `1` |
| `msg` | string | 是 | 成功固定为 `success` |
| `data.id` | number | 是 | 新用户 ID |
| `data.username` | string | 是 | 用户名 |
| `data.createdAt` | string | 是 | 创建时间 |

#### 响应示例

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": 1001,
    "username": "xiaoya",
    "createdAt": "2026-10-22T10:30:00+08:00"
  }
}
```

#### 说明

- 用户名已存在返回 HTTP `409`、`USERNAME_ALREADY_EXISTS`。
- 参数不符合长度或字符规则返回 HTTP `400`、`INVALID_PARAMETER`。
- 响应和日志均不得包含明文密码或密码哈希。

### 4.2 用户登录

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/users/login` |
| 请求方式 | POST |
| 接口说明 | 校验用户名和密码，成功后签发访问 Token |
| 登录要求 | 否 |

#### 请求参数

请求类型：`application/json`

| 参数名 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `username` | string | 是 | `xiaoya` | 注册时使用的用户名 |
| `password` | string | 是 | `XyPass123` | 用户输入的明文密码；仅 HTTPS 传输，不落日志 |

#### 请求示例

```json
{
  "username": "xiaoya",
  "password": "XyPass123"
}
```

#### 响应参数

HTTP 状态码：`200 OK`

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.accessToken` | string | 是 | 后续请求使用的访问 Token |
| `data.tokenType` | string | 是 | 固定为 `Bearer` |
| `data.expiresIn` | number | 是 | Token 有效秒数；暂定 `7200` |
| `data.user.id` | number | 是 | 用户 ID |
| `data.user.username` | string | 是 | 用户名 |

#### 响应示例

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "accessToken": "<access-token>",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "user": {
      "id": 1001,
      "username": "xiaoya"
    }
  }
}
```

#### 说明

- 用户名不存在和密码错误统一返回 HTTP `401`、`INVALID_CREDENTIALS`，避免泄露用户名是否注册。
- 首版不提供 Refresh Token；Token 签名密钥放在 Apollo/安全配置中，不写入代码仓库。

### 4.4 退出登录

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/users/logout` |
| 请求方式 | POST |
| 接口说明 | 使当前访问 Token 失效 |
| 登录要求 | 是 |

#### 请求参数

无请求体。按公共约定在请求头提供 Token。

#### 请求示例

```http
POST /api/users/logout
Authorization: Bearer <access-token>
```

#### 响应参数

HTTP 状态码：`200 OK`；`data` 为 `null`。

#### 响应示例

```json
{
  "code": 1,
  "msg": "success",
  "data": null
}
```

#### 说明

服务端将当前 Token 加入 Redis 撤销记录，保留至其过期；客户端收到成功响应后清除本地 Token。重复退出保持幂等。

## 6. 账单接口

账单金额必须大于 `0`。`transactionType` 必须与所选分类的 `type` 一致。收入与支出使用独立分类。账单归属用户由 Token 确定。

### 6.1 新增账单

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/bills` |
| 请求方式 | POST |
| 接口说明 | 为当前用户新增一笔收入或支出 |
| 登录要求 | 是 |

#### 请求参数

请求类型：`application/json`

| 参数名 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `transactionType` | string | 是 | `EXPENSE` | `EXPENSE` 支出，`INCOME` 收入 |
| `categoryId` | number | 是 | `1` | 系统分类 ID；分类必须启用且类型匹配 |
| `amount` | string | 是 | `35.50` | 大于 0，最多两位小数 |
| `transactionDate` | string | 是 | `2026-10-22` | 记账日期，不允许非法日期 |
| `remark` | string | 否 | `午餐` | 备注，最长 500 字符 |
| `mood` | string | 否 | `平静` | Demo 心情标签；是否进入首版待评审 |

#### 请求示例

```json
{
  "transactionType": "EXPENSE",
  "categoryId": 1,
  "amount": "35.50",
  "transactionDate": "2026-10-22",
  "remark": "午餐"
}
```

#### 响应参数

HTTP 状态码：`201 Created`；返回新增账单详情。

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.id` | number | 是 | 账单 ID |
| `data.transactionType` | string | 是 | 收入/支出类型 |
| `data.categoryId` | number | 是 | 分类 ID |
| `data.categoryName` | string | 是 | 分类名称快照/显示名称 |
| `data.amount` | string | 是 | 账单金额 |
| `data.transactionDate` | string | 是 | 记账日期 |
| `data.remark` | string/null | 否 | 备注 |
| `data.mood` | string/null | 否 | 心情标签 |
| `data.createdAt` | string | 是 | 创建时间 |
| `data.updatedAt` | string | 是 | 修改时间 |

#### 响应示例

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": 3001,
    "transactionType": "EXPENSE",
    "categoryId": 1,
    "categoryName": "餐饮",
    "amount": "35.50",
    "transactionDate": "2026-10-22",
    "remark": "午餐",
    "mood": "平静",
    "createdAt": "2026-10-22T12:30:00+08:00",
    "updatedAt": "2026-10-22T12:30:00+08:00"
  }
}
```

#### 说明

金额格式错误、金额小于等于零、分类不存在/停用或收支类型不匹配时，返回 HTTP `400`、`INVALID_PARAMETER`。

### 6.2 分页查询账单

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/bills` |
| 请求方式 | GET |
| 接口说明 | 按月份、收支类型和分类筛选当前用户账单并分页 |
| 登录要求 | 是 |

#### 请求参数

请求类型：query string

| 参数名 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `month` | string | 否 | `2026-10` | 按自然月筛选，格式 `YYYY-MM` |
| `transactionType` | string | 否 | `EXPENSE` | `EXPENSE` 或 `INCOME` |
| `categoryId` | number | 否 | `1` | 系统分类 ID |
| `page` | number | 否 | `1` | 页码，从 1 开始，默认 1 |
| `pageSize` | number | 否 | `20` | 每页条数，默认 20，最大 100 |

#### 请求示例

```http
GET /api/bills?month=2026-10&transactionType=EXPENSE&page=1&pageSize=20
Authorization: Bearer <access-token>
```

#### 响应参数

HTTP 状态码：`200 OK`。

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.total` | number | 是 | 符合筛选条件的总记录数 |
| `data.page` | number | 是 | 当前页码 |
| `data.pageSize` | number | 是 | 每页条数 |
| `data.rows` | object[] | 是 | 当前页账单数组，字段同 6.1 响应中的账单详情 |

#### 响应示例

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 1,
    "page": 1,
    "pageSize": 20,
    "rows": [
      {
        "id": 3001,
        "transactionType": "EXPENSE",
        "categoryId": 1,
        "categoryName": "餐饮",
        "amount": "35.50",
        "transactionDate": "2026-10-22",
        "remark": "午餐",
        "mood": "平静",
        "createdAt": "2026-10-22T12:30:00+08:00",
        "updatedAt": "2026-10-22T12:30:00+08:00"
      }
    ]
  }
}
```

#### 说明

- 排序固定为 `transactionDate DESC, id DESC`。
- 仅查询当前 Token 用户的数据。未传筛选条件时查询当前用户的全部账单。
- 页码小于 1、`pageSize` 小于 1 或大于 100 时返回参数错误。

### 6.4 修改账单

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/bills/{billId}` |
| 请求方式 | PUT |
| 接口说明 | 完整替换当前用户的一笔账单 |
| 登录要求 | 是 |

#### 请求参数

请求类型：path variable + `application/json`。`billId` 含义同 6.3；请求体字段与 6.1 相同且必填字段仍必填。

#### 请求示例

```http
PUT /api/bills/3001
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{
  "transactionType": "EXPENSE",
  "categoryId": 2,
  "amount": "42.00",
  "transactionDate": "2026-10-22",
  "remark": "打车",
  "mood": "平静"
}
```

#### 响应参数与示例

HTTP 状态码：`200 OK`；返回修改后的完整账单详情，字段同 6.1。

#### 说明

账单不存在或不属于当前用户时返回 `404 BILL_NOT_FOUND`。金额和分类校验规则同 6.1。修改账单后，预算使用情况和月度统计按最新账单重新计算。

### 6.5 删除账单

#### 接口信息

| 项目 | 内容 |
|---|---|
| 请求路径 | `/api/bills/{billId}` |
| 请求方式 | DELETE |
| 接口说明 | 删除当前用户的一笔账单；第一版采用物理删除 |
| 登录要求 | 是 |

#### 请求参数

#### 请求示例


#### 响应参数与示例

## 7. 预算接口

Demo 主 App 的编辑方式是逐项修改分类预算，总预算自动等于各分类预算之和。因此接口不单独设置总预算；月预算主记录由首次设置分类预算时创建，`totalAmount` 由服务端汇总分类额度后返回。各分类已用金额按该用户当月对应分类的支出账单汇总。总预算已用金额按当月全部支出账单汇总。

| 登录要求 | 是 |

#### 请求示例

### 7.2 设置或修改分类预算

#### 接口信息

| `categoryId` | number | 是 | `1` | 必须是启用的支出分类 |

### 9.2 开始开发前需要确认

1. **总预算规则存在冲突**：Demo 主 App 中总预算由分类预算自动汇总；当前项目规划文字写了“设置总预算”和“设置分类预算”。本接口文档按 Demo 的主页面操作设计为“总额派生，不提供单独设置总额接口”。需要将项目规格与此规则统一后再建表/实现。
2. **分类名称存在冲突**：Demo 使用“饮食”，数据库草案和项目规格使用“餐饮”；Demo 的收入表单主要展示“工资/其他”，项目规格列出“工资、奖金、兼职、报销、其他”。最终名称和初始分类清单需要统一，前端通过分类接口获取配置，不硬编码分类 ID。
3. **心情是否属于第一版**：Demo 记账表单和账单列表有心情标签，数据库草案已预留 `mood`；项目第一版功能清单尚未明确。若保留，应按本文可选字段实现；若不保留，需从数据库和 API 同步删除。
4. **认证细节**：本草案建议 Access Token 有效期 2 小时、Redis 撤销列表支持退出；上线前需确定 JWT 算法、密钥配置和 Token 实际存储策略。
5. **删除策略**：本草案按物理删除设计；如需账单恢复或审计，应在开发前改为软删除，并同步数据库与接口行为。

在以上事项确定前，此文档作为评审稿，不应直接视为最终 API 或据此生成生产数据库。
